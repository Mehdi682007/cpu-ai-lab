# CPU AI Lab

**چت هوش مصنوعی روی CPU، با رابط فارسی و نصب‌کننده منویی برای Linux و WSL2.**

دو حالت مستقل:

| محیط | آدرس چت | کنترل دسترسی |
|---|---|---|
| سرور عمومی | `https://SERVER_IP:5555` | ورود با رمز + گواهی معتبر IP |
| کامپیوتر شخصی / WSL2 | `http://localhost:5555` | فقط loopback دستگاه، بدون انتشار عمومی |

مدل روی همان سرور یا کامپیوتر نصب و اجرا می‌شود. Ollama روی اینترنت باز نمی‌شود.

## نصب سریع

روی سرور Linux یا داخل Ubuntu در WSL اجرا کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/Mehdi682007/cpu-ai-lab/main/install.sh -o cpu-ai.sh
sudo bash cpu-ai.sh
```

گزینه **۱** را انتخاب کنید. اگر با `root` وارد شده‌اید، `sudo` لازم نیست. قبل از اجرا می‌توانید فایل را بررسی کنید.

نصب تازه روی WSL به‌صورت خودکار حالت محلی را انتخاب می‌کند؛ روی سرور معمولی حالت عمومی انتخاب می‌شود. انتخاب صریح:

```bash
# فقط روی دستگاه فعلی
sudo env ACCESS_MODE=local bash cpu-ai.sh --install

# سرور با IPv4 عمومی؛ برای NAT نشانی عمومی را خودتان مشخص کنید
sudo env ACCESS_MODE=public PUBLIC_IP=YOUR_PUBLIC_IPV4 bash cpu-ai.sh --install
```

در حالت عمومی، **پورت‌های ورودی TCP 80 و 5555 باید آزاد و قابل دسترس باشند**. پورت ۸۰ برای صدور و تمدید گواهی Let's Encrypt است؛ چت از HTTPS روی ۵۵۵۵ سرو می‌شود. پورت ۴۴۳ لازم نیست. اگر ۸۰ در اختیار وب‌سرور دیگری باشد، برنامه آن را متوقف نمی‌کند. در فایروال فعال UFW/firewalld، نصب‌کننده اجازه همین دو پورت را اضافه می‌کند؛ فایروال غیرفعال را فعال نمی‌کند. فایروال ابری را باید در پنل ارائه‌دهنده تنظیم کنید.

گواهی IP کوتاه‌عمر است و Caddy آن را خودکار تمدید می‌کند؛ پورت ۸۰ را بعد از نصب مسدود نکنید. اگر گواهی معتبر صادر نشود، برنامه به HTTP عمومیِ بدون رمزنگاری برنمی‌گردد. [اطلاعات رسمی گواهی IP](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability)

## ورود و مدیریت

پس از نصب:

```bash
sudo cpu-ai
```

اگر PATH فرمان را پیدا نکرد: `sudo /usr/local/bin/cpu-ai`.

| گزینه | عملکرد |
|---|---|
| ۱ | نصب |
| ۲ | آپدیت از آخرین Release همین مخزن با بررسی SHA-256 |
| ۳ | وضعیت سرویس‌ها و آدرس دسترسی |
| ۴ | راه‌اندازی مجدد |
| ۵ | حذف برنامه با حفظ مدل‌ها و داده‌های لازم برای نصب مجدد |
| ۶ | گزارش‌ها |
| ۷ | تغییر بین IP عمومی و localhost |
| ۸ | نمایش اطلاعات خصوصی ورود، فقط در ترمینال مدیر |
| ۰ | خروج |

نام کاربری عمومی `admin` است و رمز تصادفی برای **هر نصب** روی همان میزبان ایجاد می‌شود:

```bash
sudo cpu-ai --access
```

رمز وب با رمز SSH یکسان نیست. `/etc/cpu-ai/access.txt` فقط برای root خواندنی است؛ برنامه فقط هش PBKDF2 را از فایل جداگانه می‌خواند. رمز یا کلید گواهی در این مخزن وجود ندارد.

فرمان‌های مستقیم:

```bash
sudo cpu-ai --status
sudo cpu-ai --update
sudo cpu-ai --public
sudo cpu-ai --local
sudo cpu-ai --restart
sudo cpu-ai --logs
sudo cpu-ai --uninstall
```

آپدیت، `install.sh` و checksum را از آخرین Release دانلود و بررسی می‌کند، فایل‌های قبلی را پشتیبان می‌گیرد و مدل و حالت دسترسی را حفظ می‌کند. `--repair` نسخه موجود در همان نصاب را دوباره اعمال می‌کند. نسخه موتور Ollama در این انتشار روی `0.40.6` ثابت است.

حذف، برنامه و پراکسی را متوقف می‌کند؛ مدل‌ها، runtimeها، تنظیمات ورود و cache گواهی برای نصب مجدد حفظ می‌شوند. قواعد اضافه‌شده فایروال هم خودکار حذف نمی‌شوند. هیچ سرویس نامرتبطی حذف نمی‌شود.

## WSL2 روی ویندوز

برای استفاده شخصی آینده، یک Ubuntu داخل WSL2 با systemd لازم است. روی میزبان ویندوزیِ فعلی به‌صورت خودکار WSL نصب یا تنظیم نمی‌شود.

1. در PowerShell: `wsl --install -d Ubuntu`
2. داخل Ubuntu، با `ps -p 1 -o comm=` بررسی کنید PID 1 برابر `systemd` باشد. اگر نیست، مطابق [راهنمای Microsoft](https://learn.microsoft.com/en-us/windows/wsl/systemd) آن را فعال کنید؛ تنظیمات موجود `wsl.conf` را بازنویسی نکنید.
3. دستور نصب بالا را داخل Ubuntu اجرا کنید؛ در صورت نیاز `ACCESS_MODE=local` را صریح بدهید.
4. در مرورگر ویندوز باز کنید: **http://localhost:5555**.

مدل در فایل‌سیستم همان WSL، زیر `/usr/share/ollama` ذخیره می‌شود و inference روی CPU سیستم کاربر است. بعد از دانلود اولیه، حالت محلی برای تولید پاسخ به سرویس AI خارجی نیاز ندارد. WSL باید در حال اجرا باشد. [شبکه localhost در مستندات Microsoft](https://learn.microsoft.com/en-us/windows/wsl/networking)

حالت محلی روی Linux آزمایش شده است؛ اجرای کامل داخل WSL/ویندوز هنوز تست عملی نشده و برای قسمت بعدی در نظر گرفته شده است.

## منابع مورد نیاز

- حدود ۲ GB RAM، حداقل ۲ رشته CPU قابل استفاده و ۸ GB فضای آزاد برای نصب اولیه؛
- Linux با systemd؛ x86_64 دارای AVX یا ARM64؛ Python 3.9+؛
- مسیر نصب برای Ubuntu 22.04/24.04/26.04، Debian 12/13، خانواده RHEL 9+ و Fedora؛
- دسترسی HTTPS به مخازن توزیع، GitHub و رجیستری Ollama؛ حالت عمومی همچنین به Let's Encrypt نیاز دارد.

**تست واقعی روی Ubuntu 24.04 / x86_64، دو vCPU و حدود ۲ GB RAM انجام شده است.** معماری‌ها و توزیع‌های دیگر هنوز تست عملی نشده‌اند. وجود RAM و CPU به‌تنهایی کافی نیست؛ برنامه به سرویس Ollama نامرتبط از قبل نصب‌شده دست نمی‌زند.

مدل پیش‌فرض با توجه به حافظه در دسترس `qwen2.5:1.5b` یا نسخه کم‌مصرف‌تر `qwen2.5:0.5b` است. مدل کوچک کیفیت محدود، به‌خصوص در فارسی، دارد و خروجی کد باید بررسی و تست شود.

## امکانات چت

- رابط فارسی واکنش‌گرا، حالت عمومی و کدنویسی، نمونه درخواست؛
- پاسخ تدریجی با سقف انتخابی ۵۱۲ / ۱۰۲۴ / ۲۰۴۸ توکن؛ زمینه ۴۰۹۶ توکن؛
- کادر کد چپ‌به‌راست و کپی، توقف با حفظ متن، ادامه پاسخ، دریافت مکالمه؛
- نمایش هشدار سقف پاسخ و محدودیت متن گفت‌وگو؛
- یک درخواست تولید هم‌زمان و سقف حافظه مدل معادل ۷۵٪ RAM؛
- نشست ورود با کوکی HttpOnly/Secure در حالت عمومی، خروج و محدودیت تلاش ناموفق.

حالت «کدنویسی» تنظیم دستور پاسخ است؛ مدل تخصصی Coder نصب نمی‌کند. ادامه پاسخ، صحت یا کامل‌بودن کد را تضمین نمی‌کند. تاریخچه در حافظه صفحه است و با بستن/بارگذاری مجدد پاک می‌شود.

## توسعه و تست

```bash
python3 scripts/build.py
bash -n install.sh
python3 tests/test_http.py
```

فایل `install.sh` از `src/` و `installer/` ساخته می‌شود. فایل‌های خصوصی میزبان، مدل‌ها و گواهی‌ها نباید وارد Git شوند. CI رابط HTTP را با شبیه‌سازی مرز Ollama آزمایش می‌کند؛ این تست‌ها بنچمارک کیفیت مدل نیستند.
